Trier les tickets d'un opérateur fibre avec Mistral

Chaque message client reçoit une catégorie, une urgence et une équipe destinataire. Un banc d'essai de 90 tickets, dont 48 pièges, compare les modèles Mistral à une règle par mots-clés, avec le coût et le gain réel par mois.

Cette version publie les résultats de la règle par mots-clés, qui servent de point de référence. Les modèles Mistral s'ajoutent automatiquement aux graphiques en lançant python evaluate.py avec une clé API (voir le dépôt).

Essayer

Choisis un ticket du jeu de test pour voir la réponse de chaque modèle, ou écris le tien (démo locale).

Comparaison des modèles

Les tickets « standard » ressemblent à ceux qui ont servi à écrire la règle par mots-clés. Les « difficiles » sont nouveaux : urgences implicites, ironie, SMS, anglais, demandes multiples.

Rappel des P1 = part des vraies urgences détectées comme urgentes. C'est l'indicateur le plus important : rater une panne d'EHPAD coûte plus cher que mal classer une question de facture.

Ce que ça rapporte

Les hypothèses sont à remplacer par les chiffres du client. Seuls les tickets traités automatiquement comptent (les autres partent en revue humaine), et chaque erreur de tri coûte du temps.

Les 90 tickets

Tous les tickets sont fictifs. La première colonne donne la réponse attendue, les suivantes la réponse de chaque modèle.
